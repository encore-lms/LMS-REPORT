03

아키텍처

현재 개발 환경(dev)은 실제 요청을 처리하는 API 서비스 3개와 서비스별 전용 PostgreSQL RDS로 동작합니다. integration-service는 태스크가 꺼져 있고, 증명서 분석을 맡을 LMS-AI는 아직 AWS에 배포되지 않아 8월 마감에서 이 부분을 연결해야 합니다.

요청 진입

CloudFront → ALB

CloudFront에서 HTTPS를 종단하고, 캐시 없이 ALB로 API 요청을 전달

실행 계층

ECS 3개 기동

auth · learning · operations는 각 1개 태스크, integration은 0개

데이터 경계

RDS 4대 분리

서비스별 PostgreSQL 4대 중 3대 사용, integration DB는 생성만 된 상태

8월 연결 포인트

LMS-AI 미배포

증명서 점수·서술 분석 엔진을 ECS에 배포하고 learning과 연결해야 함

1. 현재 배포 구성 실측

아래 그림은 Terraform 코드와 실제 AWS 리소스를 대조한 dev API 인프라입니다. 요청은 CloudFront와 ALB를 거쳐 퍼블릭 서브넷의 ECS로 들어가고, RDS·Redis는 인터넷 경로가 없는 프라이빗 서브넷에 둡니다. 웹 프런트 정적 배포와 로컬에서만 실행 중인 LMS-AI는 이 그림의 범위 밖입니다.

요청을 처리하는 실행 중 구성 데이터 저장소 미기동 · 보조 · 관리형

전체 요청 경로

도식 읽는 순서 4단계
1. HTTPS 진입
브라우저 → CloudFront
2. 오리진 전달
CloudFront → ALB
3. 경로 분기
ALB → auth · learning · operations
4. 데이터 접근
서비스 → 전용 RDS · Redis · S3

근거·범위 — 2026-08-06 Terraform 코드(terraform/)와 AWS 실조회 결과를 대조했습니다. 블록의 사양·기동 수는 조회 시점의 실제 값으로, 보고서 기준일(08-05)보다 하루 뒤 시점입니다. 블록을 선택하면 사양과 연결 대상을 볼 수 있고, 번호 버튼으로 요청 흐름만 따로 볼 수 있습니다.

2. 현재 규모에 맞춘 설계 판단 결정

설계 기준은 수강생 265명 · 매니저 25명(계정 약 290개)입니다. 최대 처리량을 미리 확장하기보다, 현재 규모에서 필요한 데이터·보안 경계는 유지하고 이중화와 대기 자원은 최소화했습니다.

유지한 경계

서비스별 실행·DB 분리

인증·학습·운영의 소유권을 나누고, RDS와 비밀 값도 서비스 단위로 분리했습니다.

줄인 비용

단일 태스크·단일 AZ

서비스당 태스크 1개, RDS 단일 AZ, Redis 1노드로 이중화 대기 비용을 줄였습니다.

보완한 노출

접속 경로는 최소화

ECS는 NAT 없이 공인 IP를 쓰지만 인바운드는 ALB 보안 그룹만 허용하고, RDS·Redis는 프라이빗 서브넷에 두었습니다.

오프라인 집체 교육이라 출결·로그인·과제 마감 시각에 요청이 몰릴 수 있습니다. 아래 6가지 부하 케이스는 이 운영 패턴에서 나온 설계 가설이며, 부하 실험 결과가 아닙니다.

상세 근거 — 예상 부하 6가지와 현재 처리 방식
부하 케이스 (가설) 몰리는 지점 현재 구성이 받는 방식
강의 시작 전후 10여 분에 265명이 출결 체크 learning-service 출결 API는 learning이 담당하고, 현재 512 CPU / 2048MiB 태스크 1개로 운영합니다. 피크 RPS와 여유는 부하 실험으로 확인해야 합니다.
일과 시작에 로그인·토큰 갱신이 한꺼번에 몰림 auth-user-service · Redis refresh token을 RDS가 아닌 Redis에 둬 토큰 갱신이 DB를 거치지 않습니다. 현재는 cache.t4g.micro 1노드며, 용량과 연결 수를 지표로 관찰합니다.
과제 마감 직전 파일 제출이 몰림 learning-service · S3 파일 본문은 S3로 가고 서비스는 메타데이터만 다룹니다. 대용량 제출이 태스크 메모리를 밀어내지 않습니다.
매니저 25명이 운영 대시보드를 동시 사용 operations-service 운영 경로(규칙 90)를 learning의 광역 /admin/*보다 먼저 매칭시켜 수강생 트래픽과 분리했습니다. 현재 사양은 512 CPU / 1024MiB입니다.
증명서 공개 링크로 외부 검증자가 유입 learning-service /verify/* 현재 CloudFront API 캐시는 비활성입니다. 외부 검증 트래픽이 커지면 공개 응답의 불변성과 TTL을 확정한 뒤 해당 경로만 캐시할 수 있습니다.
배포·장애로 태스크가 재시작 전 서비스 태스크가 1개뿐이라 콜드스타트(약 60초) 동안 해당 서비스가 비지만, 이 규모에선 감수합니다. 헬스체크 유예 120초로 재시작이 크래시루프가 되는 것만 막았습니다.

핵심 트레이드오프는 기본으로 펼쳐 둡니다. 아래 선택은 누락이 아니라 현재 규모에서 대기 비용을 줄이기 위한 결정이며, 감수한 위험과 후속 기준을 함께 봐야 합니다.

핵심 트레이드오프 — 줄인 비용과 감수한 위험
현재 선택 얻은 효과 감수한 위험·후속 기준
NAT Gateway 없이 ECS를 퍼블릭 서브넷에 배치 NAT 고정비와 처리량 비용 제거 태스크가 공인 IP를 가짐. 현재는 ALB 보안 그룹만 인바운드로 허용하며, 보안 기준 상향 시 NAT + 프라이빗 ECS로 이전
RDS 단일 AZ · Redis 1노드 · 서비스당 태스크 1개 이중화용 대기 자원 비용 최소화 재시작·AZ 장애 시 서비스 중단 가능. 가용성 목표가 높아지면 태스크 2개 이상과 RDS multi-AZ를 선적용
커스텀 도메인 없이 CloudFront 기본 도메인 사용 도메인·인증서 관리 범위 축소, HTTPS는 확보 웹·API 도메인 분리로 세션 쿠키가 차단될 수 있음. 8월 QA 전 도메인 정리 필요
서비스별 db.t4g.micro RDS 4대 분리 서비스별 데이터 소유권과 접근 경계 유지 integration-service가 미기동이라 전용 RDS도 미사용. 기능 폐지 범위가 고정되면 보존·제거를 다시 판단

용량 한계는 숫자로 확정하지 않음

현재는 부하 실험 결과와 피크 자원 지표가 없어 “동시 사용자 몇 명까지”를 수용 한계로 단정할 수 없습니다. 약 290개 계정을 기준으로 운영하되, Container Insights에서 CPU·메모리 75% 초과가 지속되거나 반복될 때 해당 서비스의 태스크 수와 오토스케일 기준을 재산정합니다.

04

증명서 발급 흐름 결정 08-06 개정

제품의 핵심 가치이자 현재 유일하게 끊긴 구간입니다. 08-06에 흐름을 개정했습니다 — 수강생 요청 트리거를 없애고, 수료가 확정된 다음 날 00:00 배치가 전원 생성하는 방식으로 바꿉니다. 산출물이 전부 S3 불변 파일이므로 승인 시점의 객체 버전을 그대로 동결할 수 있고, 이후 원본 데이터가 바뀌어도 발급본은 변하지 않습니다. 외부인은 공개 링크로 진위를 확인합니다.

단계 담당 현재 상태
1. 원천 스냅샷 — 수료 익일 00:00 배치가 학습·프로젝트·평가 데이터를 S3에 저장 시스템 미구현
2. 전처리 — 증명서에 표시할 항목만 가공해 cohort=N/student_uuid=… 아래 영역별(종합요약 · 기술검증 · 프로젝트 …)로 저장 시스템 미구현
3. 분석 — 6축 점수는 확정 함수, 서술만 OpenAI. scores·ai를 모델·프롬프트 버전 메타와 함께 같은 파티션에 저장 시스템 · LMS-AI 미구현 LMS-AI는 ECS 미배포
4. 준비 완료 — 학생 단위 상태로 검토 큐 등록 (한 명의 실패가 코호트 전체를 막지 않게, 실패는 학생 단위 재시도) 시스템 미구현
5. 검토 — 매니저가 미리보고 승인 또는 보완 요청(학생 단위 재처리) 운영자 백엔드 미구현 화면은 완성, 메뉴 차단
6. 승인 = 동결 — 그 시점의 S3 객체 버전 ID를 증명서에 고정 운영자 미구현
7. 열람·공개 — 수강생이 자신의 증명서를 확인하고 공개 여부 선택 수강생 공개 설정 동작 열람 화면 완성 (임시 데이터)
8. 외부 검증 — /verify/* 공개 링크로 동결 스냅샷 조회 외부 동작

이전 결정(수강생 요청 시 생성)에서 바뀐 것은 트리거 하나이며, 대가는 요청하지 않을 학생 몫까지 나가는 OpenAI 서술 비용입니다. 선행 조건은 둘입니다 — 배치 실행 주체(서비스당 태스크가 1개라 Spring @Scheduled로 충분, 오토스케일 V2 도입 시 분산 락 필요)와 LMS-AI의 ECS 배포(현재 로컬 실행만). S3 버저닝이 켜져 있어(실측) 보완 요청으로 재처리해도 승인된 발급본은 버전 ID로 불변입니다.
