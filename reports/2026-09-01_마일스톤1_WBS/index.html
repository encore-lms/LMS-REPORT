09.01 주간회의 자료

마일스톤 1
주차별 WBS

9월 11일까지 코칭 에이전트에서 실제 발생한 학습 데이터와 LMS 데이터가 합쳐진 통합 리포트를 LMS에 노출하기 위한, 양 측 업무 · 일정 · 주고받을 데이터 계획입니다.

이번 주부터 주간회의는 개발 진행 상황 설명이 아니라 이 문서의 항목을 기준으로 완료 여부를 확인하는 방식으로 진행합니다.

기준일 2026-08-31 대상 회의 2026-09-01 완료 기한 2026-09-11 (금) 남은 기간 9일 참조 08-11 GOV-AI × LMS 통합 기획안

03

주고받을 데이터 · API

양 측이 서로에게 넘겨야 할 것과 그 시점입니다. 전달 시점을 못 지키면 상대 측 업무가 그날부터 멈춥니다 — 마지막 열이 그 영향입니다.

방향 무엇을 형식 · 경로 전달 시점 없으면 막히는 것
LMS → GOV-AI 기수 · 수강생 · 학습 활동 조회 API GET /ingest/v1/courses + 전용 API 키 08-18 완료 리포트를 어느 수강생 · 어느 기수로 묶을지 판단
LMS → GOV-AI 로그인 API와 비브라우저 클라이언트용 토큰 발급 방식 POST /auth/login — 응답의 user.id가 기준 식별자 09-02 계약 ① 실습 환경 로그인 연동
GOV-AI → LMS 리포트 스키마 정의 + 샘플 리포트 1건 JSON — 아래 경로 규약 09-03 LMS 통합 파이프라인 · 검토 화면 · 수강생 화면 전부
GOV-AI → LMS S3 버킷 주소와 LMS 읽기 권한 버킷명 + 접근 권한 설정 09-03 리포트 수신 경로 구현
GOV-AI → LMS 실 수강생 대상 일자별 리포트 같은 경로에 매일 1회 09-08 통합 리포트의 실데이터, 09-11 시연
GOV-AI → LMS 리포트 재생성 API 엔드포인트 · 인증 방식 · 호출 단위 09-10 검토에서 반려한 리포트의 재생성 (없으면 매니저가 직접 수정)

경로 규약

08-11 킥오프에서 제시한 규약입니다. 09-01 회의에서 확정합니다.

GOV-AI-DATARAKE/{YYYY-MM-DD}/json

원천 데이터 — 계약 ②

GOV-AI-REPORT/{수강생 고유 번호}/{YYYY-MM-DD}/report

일자별 분석 리포트 — 계약 ③. 수강생 고유 번호는 로그인 응답의 user.id(UUID)

가장 이른 병목은 09-03 리포트 샘플입니다

LMS 측 업무 4건(통합 파이프라인 · 검토 화면 · 화면 전환 · 시연)은 전부 리포트에 어떤 항목이 담겨 오는지를 알아야 시작할 수 있습니다. 샘플 1건이면 충분하며, 완성된 분석 품질은 필요하지 않습니다.

09-02까지 회신이 없으면 LMS가 스키마 초안을 먼저 만들어 보내고 상대 측이 그 형식에 맞추는 방향으로 전환할 것을 제안합니다 — 남은 기간상 스키마 확정을 더 미룰 여유가 없습니다.

04

주차별 산출물

각 주차가 끝난 시점에 실제로 존재해야 하는 것과 그것을 확인하는 방법입니다. 주간회의에서는 설명을 듣는 대신 이 표의 확인란을 채웁니다 — 확인 방법에 적힌 대로 그 자리에서 열어 보고 O · X 를 정합니다.

1주차 — 09-01(화) ~ 09-04(금)

이 주가 끝나면 상대 측 리포트의 모양이 확정되고, LMS에 그것을 받아 둘 자리가 생깁니다.

산출물 주체 기한 확인 방법 확인
샘플 리포트 파일 1건 GOV-AI 09-03 약속된 S3 경로를 LMS가 그 자리에서 열어 내용을 봅니다 ☐
S3 버킷 접근 권한 GOV-AI 09-03 LMS 서버에서 목록 조회가 되는지 실행해 봅니다 ☐
user.id가 실린 실습 데이터 샘플 GOV-AI 09-04 샘플 1건에 식별자 필드가 들어 있는지 확인합니다 ☐
통합 리포트 필드 정의서 LMS 09-03 어느 값이 화면 어느 항목이 되는지 문서로 확인합니다 ☐
서버에서 내려오는 진단 리포트 LMS 09-04 화면이 임시 데이터가 아닌 서버 응답으로 뜨는지 봅니다 ☐
샘플 리포트 변환 결과 LMS 09-04 샘플 1건이 화면 항목으로 변환된 모습을 봅니다 ☐

2주차 — 09-07(월) ~ 09-11(금)

이 주가 끝나면 실제 수강생 데이터가 6개 관문을 끝까지 통과합니다.

산출물 주체 기한 확인 방법 확인
원천 데이터 적재분 GOV-AI 09-08 날짜 경로에 파일이 쌓이고 있는지 확인합니다 ☐
실 수강생 일자별 리포트 GOV-AI 09-08 1개 기수 · 3일 이상 분량이 경로에 있는지 셉니다 ☐
리포트 재생성 API GOV-AI 09-10 LMS 검토 화면에서 호출해 결과가 다시 올라오는지 봅니다 ☐
주간 통합 리포트 1건 LMS 09-09 실제 리포트와 LMS 학습 활동이 합쳐진 결과물을 봅니다 ☐
검토 · 승인 화면 LMS 09-09 수강생별로 승인 · 반려가 되는지 눌러 봅니다 ☐
수강생 화면의 통합 리포트 LMS 09-10 승인된 리포트가 수강생 계정에서 보이는지 확인합니다 ☐
전 구간 시연 공동 09-11 실습 로그인부터 수강생 화면까지 끊기지 않고 흐르는지 봅니다 ☐

09-11 마일스톤 1 완료 판정

아래 6개가 모두 O 여야 완료입니다. 하나라도 X 이면 그 관문의 담당과 새 완료일을 그 자리에서 정합니다.

관문 판정 기준 O / X
1 수강생 식별 실습 환경 로그인으로 데이터에 user.id가 붙는다 ☐
2 원천 적재 실습 원천이 S3에 날짜별로 쌓인다 ☐
3 일자별 리포트 분석 리포트가 수강생 · 날짜 경로에 하루 한 번 쌓인다 ☐
4 주간 통합 · 결합 주간 리포트가 LMS 학습 활동과 합쳐져 하나로 만들어진다 ☐
5 검토 · 승인 강사 · 매니저가 수강생별로 승인 · 반려한다 ☐
6 수강생 노출 승인된 통합 리포트가 수강생 화면에 실제 데이터로 표시된다 ☐

상대 측(최문창 강사) 업무의 완료일은 현재 합의된 값이 아니라 우리 측 요청 기한입니다. 09-01 회의에서 수락 · 조정한 결과를 이 문서에 반영해 다음 주부터 같은 표로 점검합니다.
