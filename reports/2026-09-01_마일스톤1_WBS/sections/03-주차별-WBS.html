1주차 — 09-01(화) ~ 09-04(금)

이 주의 목표는 “상대 측 리포트가 어떤 모양인지 확정”하고, LMS가 그것을 받아 둘 자리를 만드는 것입니다.

주체 업무 완료일 확인 가능한 산출물
GOV-AI 계약 ①~④ 수락 여부와 각 완료일 회신 09-01 회의록에 기재된 항목별 담당 · 완료일
GOV-AI 리포트 스키마 확정 + 샘플 리포트 1건 적재 09-03 약속한 S3 경로에 올라온 샘플 파일 1개 — LMS가 직접 열어 확인
GOV-AI S3 버킷 소유 주체 · 접근 권한 확정 09-03 버킷 주소와 LMS 읽기 권한 — LMS 서버에서 목록 조회 성공
GOV-AI 실습 환경 LMS 로그인 연동 (계약 ①) 09-04 로그인 후 발생한 데이터에 user.id가 실린 샘플 1건
LMS 통합 리포트 데이터 모델 확정 — 상대 리포트 + LMS 학습 활동 결합 규칙 09-03 필드 정의서 (어느 값이 어느 화면 항목이 되는지)
LMS 진단 리포트 서버 도메인 신설 — 저장 · 조회 (현재 서버 기능 없음) 09-04 화면이 임시 데이터가 아니라 서버에서 리포트를 받아오는 상태
LMS 리포트 수신 경로 구현 — 약속된 S3 경로에서 읽어오기 09-04 샘플 리포트 1건을 읽어 화면 항목으로 변환한 결과

2주차 — 09-07(월) ~ 09-11(금)

이 주의 목표는 실제 수강생 데이터를 흘려 6개 관문을 끝까지 통과시키는 것입니다.

주체 업무 완료일 확인 가능한 산출물
GOV-AI 원천 데이터 S3 적재 가동 (계약 ②) 09-08 날짜 경로에 쌓인 원천 데이터
GOV-AI 실 수강생 대상 일자별 리포트 적재 시작 (계약 ③) 09-08 최소 1개 기수 · 3일 이상 분량의 리포트가 경로에 존재
GOV-AI 리포트 재생성 API 제공 (계약 ④) 09-10 엔드포인트 · 인증 방식 전달, LMS 검토 화면에서 호출 성공
LMS 주간 통합 파이프라인 — 일자별 리포트를 주 단위로 모으고 LMS 학습 활동과 결합 09-09 실제 리포트로 만들어진 주간 통합 리포트 1건
LMS 검토 · 승인 화면 — 강사 · 매니저용 09-09 수강생별 리포트를 승인 · 반려하는 화면 동작
LMS 진단 리포트 실데이터 전환 — 임시 데이터 제거 09-10 승인된 통합 리포트가 수강생 화면에 표시
LMS 통합 검증 · 시연 리허설 09-11 6개 관문 전부 통과 — 실습 로그인부터 수강생 화면까지 한 번에 시연
